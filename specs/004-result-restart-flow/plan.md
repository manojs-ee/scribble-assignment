# Implementation Plan: Result State & Restart Flow

**Branch**: `004-result-restart-flow` | **Date**: 2026-06-04 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/004-result-restart-flow/spec.md`

## Summary

Extend `RoomStatus` with `"finished"`, set it atomically inside `submitGuess()` on the first correct guess along with `winnerId`. Add `POST /rooms/:code/restart` to reset a finished room to lobby. On the frontend, GamePage switches to an inline results view when `room.status === "finished"`, showing winner, secret word, and scoreboard. Host sees "Play Again" button; non-host sees a waiting message. After restart, polling detects "lobby" status and navigates back to LobbyPage.

## Implementation Phases

### Phase A — Backend model + service

**A1. Extend `backend/src/models/game.ts`**
- Add `"finished"` to `RoomStatus` union: `"lobby" | "playing" | "finished"`
- Add `winnerId?: string` to `Room` interface
- Add `winnerId?: string` to `RoomSnapshot` interface

**A2. Extend `submitGuess()` in `backend/src/services/roomStore.ts`**
- Add guard: `if (room.status === "finished") return { error: "already_finished" }`  (before existing `not_playing` guard, or after — position doesn't matter as long as it short-circuits)
- In the correct-guess path: after setting `room.scores[participantId] = 100`, also set `room.status = "finished"` and `room.winnerId = participantId`

**A3. Add `restartGame()` in `backend/src/services/roomStore.ts`**
- `restartGame(code: string): { error: "not_found" } | { ok: true }`
- Get room; return `not_found` if absent
- If `room.status === "lobby"` already: return `{ ok: true }` (idempotent)
- Reset: `status = "lobby"`, `strokes = []`, `guesses = []`, `scores = {}`, `currentWord = undefined`, `drawerId = undefined`, `winnerId = undefined`
- Call `saveRoom(room)`; return `{ ok: true }`

**A4. Update `toRoomSnapshot()` in `backend/src/services/roomStore.ts`**
- Add `winnerId: room.winnerId` to the snapshot object

**A5. Add route + update guess route in `backend/src/api/rooms.ts`**
- Import `restartGame` from roomStore
- Add `router.post("/:code/restart", ...)`: parse params, call `restartGame()`, 404 on `not_found`, 200 `{ ok: true }` on success
- In `router.post("/:code/guess", ...)`: add handling for `already_finished` error → 409 "Game has already finished"

### Phase B — Frontend types + API + store

**B1. Update `frontend/src/services/api.ts`**
- Extend `RoomSnapshot.status` to `"lobby" | "playing" | "finished"`
- Add `winnerId?: string` to `RoomSnapshot`
- Add `restartGame(code: string)` API function: `POST /rooms/:code/restart` returning `{ ok: boolean }`

**B2. Update `frontend/src/state/roomStore.ts`**
- Add `restartGame()` action: calls `api.restartGame(room.code)`

### Phase C — GamePage results view

**C1. Update `frontend/src/pages/GamePage.tsx`**
- Add "finished" branch to the render: when `room.status === "finished"`, render results panel instead of canvas+guessform
- Results panel shows:
  - Winner's name: `room.participants.find(p => p.id === room.winnerId)?.name ?? "Unknown"`
  - Secret word: the `room.word` field (visible to drawer via participantId filtering) — for results, all players should see the word; this requires passing `participantId` so the backend sends `word` to the drawer, but non-drawers won't get it from the backend. **Solution**: store the word in frontend state when the drawer receives it, OR simply show the word from the guess history (the winning guess text). Using the winning guess text is simpler and works for all participants.
  - Final scoreboard: reuse `<Scoreboard>` component
  - Host: "Play Again" button calling `roomStore.restartGame()`; on success navigate to `/lobby`
  - Non-host: "Waiting for the host to start a new game..." message
- Keep the existing `room.status === "playing"` branch unchanged

**C2. LobbyPage — detect restart via polling**
- No code change needed. LobbyPage already navigates to `/game` when `room.status === "playing"`. After restart, `room.status === "lobby"` so clients on the game/results page need to navigate back to lobby.
- Add a `useEffect` in `GamePage.tsx`: when `room.status === "lobby"` (detected via poll after restart), navigate to `/lobby`.

### Phase D — Validation

- Two-tab test: start game, submit correct word → both tabs show results screen within ~2s
- Tab 1 (host/drawer): sees winner name, secret word (from winning guess), scoreboard, "Play Again" button
- Tab 2 (guesser/winner): sees same results, no Play Again button, sees waiting message
- Tab 1: click "Play Again" → both tabs navigate back to lobby within ~2s
- Start another game from lobby — confirm it works
- Run `npm run build` in both `backend/` and `frontend/`

## Key Invariants

1. `submitGuess()` sets `status = "finished"` and `winnerId` atomically in the same `saveRoom()` call — no two-step transition.
2. `restartGame()` is idempotent — calling it on a "lobby" room is safe and returns success.
3. The results screen uses the **winning guess text** (from `room.guesses`) to display the secret word to all players — avoids needing backend to send `word` to non-drawers.
4. After restart, `GamePage`'s polling detects `room.status === "lobby"` and navigates to `/lobby` — no new mechanism needed.
5. `"finished"` guard in `submitGuess()` must come before the `"not_playing"` guard — or replace it — since "finished" is also not "playing". Simplest: change `room.status !== "playing"` to explicitly handle all non-playing states.
