# Implementation Plan: Game Start & Drawer Flow

**Branch**: `002-game-start-drawer-flow` | **Date**: 2026-06-04 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/002-game-start-drawer-flow/spec.md`

## Summary

Add `POST /rooms/:code/start` to transition a room from "lobby" to "playing", assign the host as drawer, and select a secret word deterministically (by room creation index, never `Math.random()`). The word is returned only to the drawer via `?participantId=` filtering on `GET /rooms/:code`. The frontend GamePage polls every 2s and shows role-appropriate UI. Player name validation (trim + reject empty) is added to the Create and Join forms.

## Implementation Phases

### Phase A — Backend model + service

**A1. Extend types in `backend/src/models/game.ts`**
- `RoomStatus`: add `"playing"` to the union
- `Room`: add `drawerId?: string`, `currentWord?: string`, `wordIndex: number`
- `RoomSnapshot`: add `drawerId?: string`, `word?: string`

**A2. Extend `backend/src/services/roomStore.ts`**
- Add `let roomCreationCount = 0` at module level
- In `createRoom()`: increment counter, set `room.wordIndex = roomCreationCount % STARTER_WORDS.length`
- Add `startGame(code: string)`:
  - Get room; return `{ error: "not_found" }` if absent
  - Return `{ error: "already_playing" }` if `room.status === "playing"`
  - Set `room.status = "playing"`, `room.drawerId = room.hostId`, `room.currentWord = STARTER_WORDS[room.wordIndex]`
  - Call `saveRoom(room)`, return cloned room
- Update `toRoomSnapshot(room, viewerParticipantId)`:
  - Include `drawerId: room.drawerId`
  - Include `word: room.currentWord` **only** when `viewerParticipantId === room.drawerId`

**A3. Add route in `backend/src/api/rooms.ts`**
- `router.post("/:code/start", ...)` — parse params with `roomCodeParamsSchema`
- Call `startGame(code.toUpperCase())`
- On `not_found` → 404; on `already_playing` → 409; on success → 200 with `RoomSessionResponse` shape (participantId = room.drawerId, room = snapshot with word)

**A4. Schema addition in `backend/src/api/schemas.ts`**
- No new schemas strictly needed — `roomCodeParamsSchema` already handles the `:code` param; confirm no body schema required for this endpoint

### Phase B — Frontend types + API client

**B1. Update `frontend/src/services/api.ts`**
- Extend `RoomSnapshot`: `status: "lobby" | "playing"`, add `drawerId?: string`, `word?: string`
- Add `startRoom(code: string)`: `POST /rooms/:code/start` returning `RoomSessionResponse`

**B2. Update `frontend/src/state/roomStore.ts`**
- Add `startRoom()` action: calls `api.startRoom(room.code)`, calls `setRoomSession(response)`

### Phase C — Frontend pages

**C1. `LobbyPage.tsx` — wire Start Game to POST /start**
- Replace `onClick={() => navigate("/game")}` with an async handler:
  - Call `roomStore.startRoom()`
  - On success: navigate to `/game`
  - On error: display error message (e.g., "Could not start game — try again")

**C2. `GamePage.tsx` — polling + role UI**
- Add `useEffect` polling interval (~2s) calling `roomStore.fetchRoom()`, cleanup on unmount — mirror LobbyPage's pattern exactly
- Compute `isDrawer = room.drawerId === participantId`
- Replace placeholder canvas area with role display:
  - Drawer: show "You are the drawer" heading + secret word (`room.word`)
  - Guesser: show "You are guessing" heading (no word)

**C3. `CreateRoomPage.tsx` — name validation**
- On submit: trim name, check length; if empty set local error state "Name is required", return early
- Clear error when user modifies the input

**C4. `JoinRoomPage.tsx` — name validation**
- Same trim + empty check as C3 (room code trim already exists from Scenario 1)

### Phase D — Validation

- Start backend and frontend dev servers
- Open two browser tabs; create room in Tab 1, join in Tab 2
- Click Start Game in Tab 1 → both tabs navigate to `/game`
- Tab 1 (drawer): sees "You are the drawer" + word
- Tab 2 (guesser): sees "You are guessing", no word
- Inspect network response in Tab 2 — confirm `word` absent from JSON
- Restart server, repeat → confirm same word for same room creation sequence
- Test name validation: enter spaces only in Create and Join forms → error appears, no API call
- Run `npm run build` in both `backend/` and `frontend/` — both must pass

## Key Invariants

1. `wordIndex` is set at **room creation**, not at game start — prevents sequence drift if other rooms are created between create and start.
2. `word` is omitted (not `null`) from the snapshot when viewer is not the drawer — no client-side hiding needed; the secret never travels over the wire to guessers.
3. `POST /rooms/:code/start` is idempotent in the failure case (409 on re-call) and never changes an already-playing room.
4. The LobbyPage polling `useEffect` does not need to be changed — it continues running until navigation.
